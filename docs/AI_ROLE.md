# AI 파트 설계 설명 — 청년서랍 / YPC

> 발표·제출 자료용. "AI 가 무엇을 하고 무엇을 하지 않는가"와 "틀리지 않게 만든 장치"를 설명한다.
> 코드 위치와 실측치는 2026-09-19 기준 (`ai/agents-a1-a2` 브랜치, PR #1).

---

## 1. 한 줄 원칙

**AI 는 공고문을 읽고, 코드는 판정한다.**

AI 가 하는 일은 세 가지뿐이다 — 공고문의 자연어 조건을 규칙으로 옮기기(A2), 부족한 정보를 물을 문구 만들기(C1), 판정 결과를 사람 말로 풀기(C2). 누가 적격인지, 언제부터 가능한지, 어떤 조합이 최선인지는 전부 결정론 코드(룰 엔진·솔버·플래너)가 계산한다. AI 출력이 판정을 바꾸는 경로는 존재하지 않는다.

```
공고문 텍스트 ──A2──▶ PolicySchema(규칙+근거) ──▶ 룰 엔진 ──▶ 판정 ──C2──▶ 설명문
                                                     │
                                          UNKNOWN ──C1──▶ 역질문 ──▶ 답변 ──▶ 재판정
```

---

## 2. 왜 이 구조인가

기존 청년정책 서비스가 못 하는 것: "**왜** 안 되는지, **언제** 되는지, **뭘 같이** 받을 수 있는지". 이걸 LLM 에게 직접 물으면 그럴듯한 답이 나오지만 검증할 수 없다. 금액·기간·조건을 지어내면 사용자가 실제 손해를 본다.

그래서 LLM 을 **구조화 도구**로만 쓴다. LLM 이 낸 것은 전부 "제안"이고, 코드가 원문과 대조해 통과한 것만 규칙이 된다. 규칙이 되고 나면 그다음은 numpy 벡터 연산이다 — 같은 입력에 항상 같은 답.

## 3. 환각 차단 — 4겹

| 겹 | 장치 | 막는 것 | 코드 |
| --- | --- | --- | --- |
| 1 | **인용문 원문 대조** — 모든 규칙·서류·상충·금액·전화번호에 `source_quote` 가 붙고, 그 문자열이 공고문 원문의 연속 구간이어야 한다 (공백 차이만 허용). 아니면 그 항목은 통째로 버림 | 문장을 다듬거나 지어낸 조건 | `batch/agents/text.py::quote_found` |
| 2 | **API 코드와 불일치 검사** — 온통청년 API 가 코드로 준 조건(나이·지역·혼인 등)과 텍스트 해석이 다르면 어느 쪽도 확정하지 않고 검토 큐로 | 한쪽을 골라 틀리는 것 | `batch/agents/structure.py::merge` |
| 3 | **표현 불가 조건은 규칙으로 만들지 않음** — 무주택·세대주·보증금·재산·기간 창(1.1~6.30 전입) 등 사용자 필드로 못 옮기는 조건은 `unrepresentable_conditions` 로 기록. 억지로 근사하지 않음 | "비슷한" 규칙이 사용자를 잘못 탈락시키는 것 | 프롬프트 `a2_structure.md` + 출력 스키마 |
| 4 | **출력 스키마로 잠금** — 모델이 만들 수 있는 필드·연산자·분류·서류명이 enum 으로 고정. 지역 코드와 정책 ID 는 스키마에 없어서 만들 수 없음 | 엔진이 모르는 필드, 솔버가 못 읽는 분류 | `batch/agents/contract.py` |

C2 설명문에는 다섯 번째 겹이 있다: **설명 속 모든 숫자는 판정 결과 안에 있어야 한다.** 하나라도 없으면 그 설명은 버리고 템플릿 문장을 쓴다 (`app/llm/explain.py::_grounded`).

| E2E 스크립트 | `tools/demo_scenario.py` | 시나리오 1~6 HTTP 재현 |
| **MCP 서버** | `tools/mcp_server.py`, `.mcp.json` | 판정 API 를 Claude Code 의 도구로. Claude 가 대화형 코디네이터가 되고 판정은 여전히 코드가 |

LLM 호출은 `app/llm/client.py` 한 곳. 모델은 Claude Opus 5, 구조화 출력(JSON Schema 강제), 프롬프트 캐시. 정책 1건 = 호출 1회.

### 4-1. MCP — "클로드 코드를 창의적으로 활용" 에 대한 답

경진대회 심사기준 1번이 *클로드 코드의 기능을 창의적으로 활용한 정도*다. 코드를 Claude Code 로 짠 건 모든 팀이 같다.
이 프로젝트는 **Claude Code 자체를 제품의 대화 인터페이스**로 쓴다:

```
사용자 ──(대화)──▶ Claude Code ──(MCP 도구)──▶ 판정 API (결정론)
                       │ find_region_code · judge · questions · combinations · plan · policy
                       └── 역질문·설명은 Claude 가 말로, 판정·날짜·조합은 코드가 숫자로
```

- 심사위원 앞에서 Claude Code 를 열고 "나 24살이고 용인 수지구 살아…" 라고 치면 끝. 화면(FE) 없이도 전체 흐름이 시연된다.
- **API 키가 필요 없다.** 대화하는 LLM 은 시연자의 Claude 구독이고, 판정은 우리 서버다.
- 설계 원칙이 그대로다: Claude 는 도구를 고르고 결과를 옮길 뿐, `judge` 가 준 verdict 를 바꿀 수 없다. 서버 지시문(instructions)에 "결과에 없는 금액·날짜를 말하지 마라"가 박혀 있다.
- 교육 3일차(MCP 연동)와 4일차(멀티에이전트) 내용을 실제 제품에 적용한 형태.

## 5. 실측 — 실제 공고 11건으로 시나리오 6개

| # | 시나리오 | 데모 사용자 | 결과 |
| --- | --- | --- | --- |
| 1 | 신청 가능 | 25세 가평 미혼 1인가구 · 소득 90% | 가평 청년 월세 `ELIGIBLE` (CONFIRMED), 조건 5개 근거 첨부 |
| 2 | 부적격 + 사유 | 56세 | 나이 `INELIGIBLE`, "시간이 지나도 충족 불가" |
| 3 | FUTURE_PASS | 23세 수원 거주 6년 | 청년기본소득: **"2026-10-15부터 충족돼요"** |
| 4 | 역질문 → 재판정 | 24세 용인 대학생 · 소득 미입력 | 용인 중개보수 `NEEDS_INFO` → 질문 1개(소득) → 120% 답변 → `ELIGIBLE` |
| 5 | 중복수혜 → 조합 | 가평 · 소득 55% | 가평 월세 + 국토부 청년월세 둘 다 적격 → **보수 조합 480만원(하나만, 제외 사유 인용) / 최대 조합 540만원(둘 다)** |
| 6 | 서류 → 일정 | 가평 | 서류 10종 중 7종 마스터 매칭, 마감 9/30 → 권장 착수 9/22, `ON_TRACK` |

설명문 예시 (템플릿, LLM 없이):

> '2026 경기도 청년기본소득 3분기'은(는) 지금 기준으로 조건 1개가 맞지 않아요. 나이: 내 값 23세, 공고 기준 24세 ("지원 대상 연령 24세 ~ 24세"). 이 조건은 2026-10-15부터 충족돼요. 다른 조건 2개는 충족했어요.

## 6. 실데이터에서 본 것 (온통청년 API, 2026-09-19, 2,819건)

- 자유 텍스트 필드 10종, 정책당 중앙값 410자 → LLM 1회 호출로 충분
- 공개 중 1,596건에서 조건 키워드: **중위소득 118 · 무주택 67 · 유사사업 45 · 기초수급 41 · 중복수혜 40 · 거주기간 17 · 재직기간 16**
- 해석: A2 가 새로 만드는 규칙의 대부분은 **소득 비율**, 무주택·재산·수급은 **규칙화 불가**로 남는다 → 그런 정책은 판정이 맞아도 "확인 필요"로 보여야 한다 (BE 미결 #10)
- 실제로 API 코드와 본문이 다른 정책이 있다 (`sprtTrgtMaxAge=39` vs 본문 "34세 이하") → 2겹 검사가 실전에서 필요함을 확인

비용 추정: Opus 5 기준 정책당 약 $0.03, 공개 1,596건 ≈ $50. Haiku 4.5 + Batch API 면 ≈ $5. 응답은 `data/a2-cache/` 에 캐시되어 재실행은 무료.

## 7. 정직하게 남긴 것

- **실제 Anthropic 키로는 아직 실행하지 않았다.** 검증·병합·채점 로직은 가짜 LLM 으로 테스트(약 90건). 11건의 구조화 응답은 사람이 프롬프트 규칙대로 작성해 **같은 검증 경로**를 통과시킨 것이다. 그 리허설에서 나온 애매한 표현 8가지("이하 없는 180%", 유형별 조건, "부부 중 1명", 기간 없는 유사사업 이력 등)를 프롬프트에 반영했다. 첫 실행 계획: `--limit 11` → 골든 채점(기준선 31/31) → 프롬프트 교정.
- 원문 공고문 크롤러(`batch/crawl`)는 없다. 지금은 API 자유 텍스트 필드만 쓴다. 11건 모두 그걸로 충분했다.
- BE 에 넘긴 미결: 표현 불가 표식의 confidence 반영(#10), 충족 예상일의 룰 간 모순(#12), 마감 지난 정책이 조합에 들어감(#13), 마스터에 없는 서류(#14), **지역 코드 단위 불일치 — 시 코드 사용자가 경기도 정책 801건에서 부적격(#15)**.

- "옮길 수 없는 조건은 억지로 옮기지 않고 '확인 필요'로 남깁니다. 틀린 부적격보다 정직한 미확정이 낫습니다."
- "판정은 numpy 로 0.1ms 에 끝납니다. LLM 은 그 앞(구조화)과 뒤(설명)에만 있습니다."
- "같은 공고를 두 모델이 다르게 읽으면, 그 조건은 담당부서 전화번호와 함께 나갑니다."
