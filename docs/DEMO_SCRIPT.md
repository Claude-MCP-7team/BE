# 데모 영상 녹화 대본 — Claude Code + MCP

발표자료용 데모 영상을 찍을 때 그대로 따라가는 대본이다. 화면은 **Claude Code 한 창**이고,
판정은 뒤에서 도는 API 서버가 한다. 아래 숫자는 전부 실제로 돌려 받은 값이다 (2026-09-29 확인).

## 기준일을 2026-09-24 로 고정한다

`data/demo/policies.demo.json` 은 실공고 31건이고 신청기간이 짧다. 고정하지 않으면
녹화하는 날에 따라 게시 건수가 달라져 **준비한 설명과 화면의 숫자가 어긋난다.**

```
2026-09-24 → 23건 게시    2026-10-01 → 17건    2026-11-01 → 12건
```

E2E 테스트(`tests/e2e/test_demo_scenarios.py` 의 `DEMO_TODAY`)와 FE Mock
(`tools/record_mock_responses.py` 의 `FIXED_TODAY`)도 같은 날짜다. 세 군데가 갈라지면
FE 가 보는 Mock 과 발표에서 도는 화면이 달라진다.

## 준비 (2분)

### 1. 스냅샷 빌드 — 기준일을 환경변수로 준다

`YPC_FIXED_TODAY` 는 빌더와 서버가 **둘 다** 읽는다 (`app/core/clock.py`). 빌드 때
주지 않으면 오늘 기준으로 마감 공고가 걸러져서, 서버에서 날짜를 고정해도 23건이 안 된다.

```bash
YPC_FIXED_TODAY=2026-09-24 python -m batch.build_snapshot data/demo/policies.demo.json -o data/demo/snapshot.json
```

`통과 23건 · 거부 0건 · 미게시 8건(expired)` 이 나와야 한다.

### 2. API 서버 기동

```bash
SNAPSHOT_PATH=data/demo/snapshot.json YPC_FIXED_TODAY=2026-09-24 CORS_ORIGINS=http://localhost:3000 python -m uvicorn app.main:app --port 8765
```

PowerShell 이면:

```powershell
$env:SNAPSHOT_PATH="data/demo/snapshot.json"; $env:YPC_FIXED_TODAY="2026-09-24"; $env:CORS_ORIGINS="http://localhost:3000"; python -m uvicorn app.main:app --port 8765
```

### 3. 녹화 전 확인 — 이 숫자가 다르면 찍지 마라

```bash
curl http://127.0.0.1:8765/readyz
```

```json
{"ready": true, "policy_count": 23, "rule_count": 51, ...}
```

`policy_count` 가 23 이 아니면 기준일이 안 먹은 것이다. 1번을 다시 한다.

### 4. Claude Code 를 저장소 폴더에서 연다

`.mcp.json` 이 `YPC_API_BASE=http://127.0.0.1:8765` 로 이 서버를 가리키고 있어서
따로 등록할 게 없다. `ypc` 도구 6개(`find_region_code` · `judge` · `questions` ·
`combinations` · `plan` · `policy`)가 보이면 준비 끝이다.

도구가 안 보이면 `pip install -e ".[mcp]"` 를 먼저 한다.

### 녹화 도구

Windows 는 `Win + Alt + R` (Xbox Game Bar) 로 활성 창만 녹화된다. 터미널 글자를
미리 키워 두면(Ctrl + `+`) 슬라이드에 넣었을 때 읽힌다.

## 대본 — 5비트, 약 3분

말은 그대로 타이핑해도 되고 바꿔도 된다. **중요한 건 지역 코드를 직접 주지 않는 것**이다.
Claude 가 `find_region_code` 를 먼저 부르는 게 화면에 보여야 한다.

### 비트 1 — 지역을 사람 말로 (20초)

> 나 2003년 3월 15일생이고 가평 살아. 대학 졸업하고 지금 취업 준비 중이야.
> 혼자 살고 미혼이고, 2022년 1월부터 가평에 살았어. 받을 수 있는 청년정책 있어?

**화면에서 짚을 것**: `find_region_code("가평")` → `41820` 을 먼저 부르고 나서
`judge` 를 부른다. 사용자는 법정동 코드를 모른다.

> 말할 거리: 구가 있는 시(수원·성남·용인 등)를 시 이름만으로 물으면 구 목록을 돌려주고
> 되묻는다. 시 코드로 판정하면 구 단위로 적힌 공고가 목록에서 통째로 사라진다.

### 비트 2 — 판정 결과와 근거 (40초)

`judge` 결과:

```
적격 7 · 확인필요 2 · 충족예상 1 · 부적격 14      (23건 중)
```

**짚을 것 셋**:

1. **적격에도 원문 인용이 붙는다** — `matched` 의 `source_quote`. 왜 되는지도 보여준다.
2. **부적격 사유가 원문이다** — 포천 프로그램(`GG-12048`):
   `region_code: 내 값 41820 / 필요 41650`, 근거 `"시행 지역 zipCd: 41650"`,
   `time_satisfiable: false` — 사는 곳은 기다려도 안 바뀌니 없는 희망을 주지 않는다.
3. **충족예상은 날짜로** — 경기도 청년기본소득(`JB-5885`): 24세 전용이라 지금은 부적격인데
   **2027-03-15 부터** 해당된다. "안 됨"이 아니라 "언제부터 되는지"를 준다.

> 말할 거리: 이 프로젝트에서 가장 나쁜 실패는 틀린 답이 아니라 **조용한 누락**이다.
> 정책이 목록에서 빠지면 사용자는 부적격도 확인필요도 아닌 아무것도 못 본다.

### 비트 3 — 역질문 하나가 정책 둘을 가른다 (30초)

> 소득은 잘 모르겠는데 뭘 더 알려줘야 해?

`questions` 결과 — 질문이 **필드별로 병합**되어 하나만 나온다:

```
household_income_ratio_median   resolves=2   answer_type=number
근거: "소득기준 : 1인 가구 기준 중위소득 150% 이하"
```

**짚을 것**: `resolves=2` — 이 답 하나로 판정이 끝나는 정책이 2건이다. 정책마다 물었다면
사용자는 같은 소득을 두 번 답한다.

### 비트 4 — 자연어로 답하면 재판정 (40초)

> 건강보험료로 보면 한 85% 정도요

**짚을 것**: `"한 85% 정도요"` 라는 말이 `85` 라는 정수로 바뀌어 판정에 들어간다
(`app/llm/answers.py`). 결과:

```
적격 8 · 확인필요 0 · 부적격 15 · 충족예상 1
```

같은 답 하나가 **가평 월세는 적격**(150% 이하)으로, **농식품 바우처는 부적격**(32% 이하가
아니라서)으로 갈린다.

> 말할 거리: 못 알아들은 답은 추측하지 않고 **버린다**. 그러면 그 필드가 다시 UNKNOWN 이
> 되어 한 번 더 묻게 된다. 잘못 바꾼 값은 확신에 찬 오판정이 되고, 다시 묻는 건 그냥
> 한 번 더 묻는 것이다.

### 비트 5 — 서류와 일정 (50초)

> 가평 월세 신청하려면 뭐 준비해야 해? 언제까지 해야 돼?

`plan` 결과 — 가평 월세(`GG-12010`):

```
status: INFEASIBLE          마감 2026-09-30
마감까지 영업일 1일          준비에 필요한 영업일 3일          여유 -2일
서류 10종
```

**짚을 것**: 기준일이 추석 연휴 한가운데(9/24~25, 9/28 대체공휴일)다. 달력을 안 보고
"일주일 남았다"고 세면 사용자를 **못 보낼 신청에 보낸다.** 영업일로 세니까 못 한다고 말한다.

서류에서 짚을 것 둘:

- **발급 소요일이 서류마다 다르다** — 지방세 미과세증명서·본인신용정보조회서는 2일,
  주민등록표 등본은 즉시. 합(0+0+2+2+…)이 아니라 **최댓값**으로 센다. 서류는 한 번에
  같이 떼기 때문이다. 합으로 세면 모든 정책이 '급함'으로 떠서 무엇이 진짜 급한지 구별이 사라진다.
- **모르는 건 모른다고 표시한다** — `마스터 미검증` 배지. 이건 "검증 안 된 서류"가 아니라
  **검증 축 둘 중 하나라도 비어 있다**는 뜻이다 (`app/planner/documents.py`
  `is_fully_grounded`):

  | 축 | 뜻 | 36종 중 |
  | --- | --- | --- |
  | `verified` | 소요일·수수료를 공적 출처에서 확인 | 23종 |
  | `validity_grounded` | 유효기간에 법령 근거가 있다 (또는 만료 개념 없음) | 5종 |
  | **둘 다** | 화면에서 딱지를 뗄 수 있다 | **1종** |

  정부24 민원안내 페이지는 **유효기간을 적지 않는다.** 소요일만 확인하고 딱지를 떼면
  근거 없는 유효기간이 검증된 값처럼 보이고, "너무 일찍 떼면 제출일에 만료" 하한이
  틀려서 소요일이 맞아도 계획이 어긋난다.

  > 말할 거리: 배지가 많이 붙는 게 부끄러운 게 아니라 **그게 기능이다.** 발급 소요일을
  > 모르는 서류를 "즉시 발급"으로 채우면 사용자는 마감을 놓치고, 그 실패는 신고도
  > 안 들어온다. 숫자를 물으면 "유효기간 근거는 아직 1종만 확보했고, 나머지는 그렇게
  > 표시하고 있다"고 그대로 답하면 된다.

### 마무리 한 줄

Claude 가 도구를 고르고 결과를 말로 옮기지만, **판정은 하지 않는다.** 나이·마감·영업일·
조합은 전부 서버의 결정론 코드가 계산하고, 화면에 나가는 모든 조건에는 공고 원문 인용이
붙어 있다. 근거 없는 룰은 DB 제약으로 저장 자체가 안 된다.

## 찍지 말 것

- **조합 추천 두 안 비교** — 보수/최대 조합이 **같은 값으로 나온다**(둘 다 1,496,000원 / 8건).
  지금 스냅샷에는 '동시에 적격인 상충 정책 쌍'이 없다. 상대였던 국토부 청년월세는
  신청기간이 2026-05-29 에 끝나 스냅샷에서 빠진다 (HANDOFF §8 #16). 두 안을 나란히
  보여주면 "왜 같아요?"라는 질문만 받는다. 조합을 넣고 싶으면 **"8건을 함께 받으면
  약 150만원"** 한 줄로만 쓴다.
- **`/v1/policies` 목록 페이지** — 카드 대부분이 `dept_tel: null` 이다. 연락처는 API
  구조화 필드에 없고 공고문 본문에서 뽑아야 해서, A2 를 거친 공고만 가지고 있다.
